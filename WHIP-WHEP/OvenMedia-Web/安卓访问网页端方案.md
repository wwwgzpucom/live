# 方案：安卓端访问网页端（复用 OvenMedia Web 三件套）

> 产品思路：**先不做原生推拉流**，安卓 App 打开我们自己的 H5 直播页；页内使用官方 **OvenLiveKit + OvenPlayer**，源站用 **OvenMediaEngine**。  
> 对应 Web 文档见同级目录 [`README.md`](./README.md)、[`搭建文档.md`](./搭建文档.md)。

---

## 1. 方案一句话

安卓负责壳（登录、房间列表、打开页面）；**直播能力全部在网页端**，与浏览器共用同一套 OvenMedia 三件套。

```text
┌─────────────────────────────────────────┐
│  Android App（始终在本壳内）              │
│  · 登录 / Token / 房间列表               │
│  · WebView 打开 H5（不跳转系统浏览器）    │
└─────────────────┬───────────────────────┘
                  │ HTTPS 加载
                  ▼
┌─────────────────────────────────────────┐
│  你们的 H5 直播页（自建站点）             │
│  · 主播页：OvenLiveKit-Web（WHIP 推流）  │
│  · 观众页：OvenPlayer（WebRTC / LLHLS）  │
└─────────────────┬───────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────┐
│  OvenMediaEngine（OME）                  │
└─────────────────────────────────────────┘
```

---

## 2. 为什么这样定

| 点 | 说明 |
|----|------|
| 复用官方最完整 Web 方案 | 推流 / 播放 / 源站一套齐，少造轮子 |
| 安卓与浏览器体验统一 | 同一 H5，两端行为一致，改一处两边生效 |
| 上线快 | App 侧主要是 WebView + 业务接口，不必先啃原生 WebRTC |
| **始终在壳内** | 直播与站点页面只在 App WebView 中打开，**不**跳转系统浏览器 |
| 后续可演进 | 开播体验不够时，再把主播端换成原生 WHIP；观众可继续用 H5 |

---

## 3. App 怎么打开直播页

**唯一方式：App 内 WebView**（不采用系统浏览器 / Custom Tabs）。

- 加载地址示例：`https://live.example.com/room/{roomId}?token=...&role=host|audience`
- 页面根据 `role` 决定挂载 **OvenLiveKit**（主播）或 **OvenPlayer**（观众）
- Token 由你们业务后端签发，H5 与 OME（或网关）做鉴权
- OME / CDN 若与主站不同域，须加入 `external.url.exception.list`，保证仍在壳内打开

---

## 4. H5 页面职责（与安卓分工）

| 层级 | 负责 |
|------|------|
| **安卓** | 登录、拉房间列表、拼带 Token 的直播 URL、打开 WebView、申请相机/麦克风权限（开播时）、返回键与生命周期 |
| **H5** | OvenLiveKit 推流、OvenPlayer 播放、开关麦/摄像头 UI、与业务后端房间状态同步 |
| **OME** | 收 WHIP、出 WebRTC / LL-HLS |

典型 URL 形态（媒体层，HOST 为 OME 地址）：

| 角色 | H5 内使用的媒体地址 |
|------|---------------------|
| 主播推流 | `http(s)://HOST:3333/app/{stream}?direction=whip` |
| 观众低延迟 | `ws(s)://HOST:3333/app/{stream}` |
| 观众可扩规模 | `http(s)://HOST:3333/app/{stream}/llhls.m3u8` |

流名 `{stream}` 建议与房间号或后端分配的流 ID 一致。

## 5. 实施顺序（建议）

1. **起 OME**：按 [`搭建文档.md`](./搭建文档.md) / [`../服务器/OME`](../服务器/OME)  
2. **起网页端**：打开 [`web/`](./web/)，改 `config.js` 的 `omeHost`，用静态服务访问  
3. **安卓壳**：WebView 打开 `web/index.html`（或你们域名上的同款 H5）  
4. **鉴权与房间**：业务后端发 Token、创房（后续加）  
5. **（可选）** 主播端改为原生推流

## 6. WebView 注意点（安卓）

| 项 | 建议 |
|----|------|
| HTTPS | 公网必须 HTTPS；否则 getUserMedia / 部分浏览器能力受限 |
| 权限 | 开播前申请 `CAMERA`、`RECORD_AUDIO`；WebView 需把权限结果交给页面（`WebChromeClient.onPermissionRequest`） |
| JS | `settings.javaScriptEnabled = true`；按需 `domStorageEnabled` |
| 硬件加速 | 播放页建议开启，减少花屏 |
| 后台 | WebView 进后台可能停采集；产品上提示「保持前台开播」或后续改原生 |
| 混合内容 | 若 H5 是 HTTPS、OME 仍是 HTTP，可能被拦；生产应给 OME 上 TLS 或同源反代 |

示意（关键回调，非完整工程）：

```kotlin
webView.webChromeClient = object : WebChromeClient() {
    override fun onPermissionRequest(request: PermissionRequest?) {
        // 已获系统相机/麦克风权限后：
        request?.grant(request.resources)
    }
}
webView.settings.javaScriptEnabled = true
webView.loadUrl(liveRoomHttpsUrl)
```

## 8. 与「原生 SDK」的关系

| 阶段 | 做法 |
|------|------|
| **当前方案（本文件 + android/）** | 安卓 = WebView 壳；媒体 = OvenMedia Web 三件套 |
